D DEVORCHESTRATE02 / Operating model

The philosophy

Authority stays with the developer.

Agents bring expertise and execution. Humans decide scope, trade-offs, and when to proceed.

Decision owner
Human Developer

Defines the requirements and acceptance criteria.

Chooses, revises, or rejects implementation plans.

Authorizes phases, review fixes, and PR creation.

⇄
Specialized assistants
AI Agents

Investigate the workspace and propose realistic options.

Implement only the approved work and verify actual outcomes.

Report trade-offs, findings, evidence, and blockers.

✓ No automatic agent chaining✓ No silent scope changes✓ No unapproved PRs

D DEVORCHESTRATE04 / Planner agent

The foundation

The Planner produces decisions,
not vague suggestions.

01. Read the real workspace

Inspect spec.md, packages, classes, methods, dependencies, tests, and conventions.

02. Reuse before creating

Identify existing services, utilities, patterns, and where reuse is inappropriate.

03. Design feasible alternatives

Compare implementation approaches with benefits, demerits, risk, and effort.

04. Write executable blueprints

Map actual files, signatures, logic, phases, acceptance criteria, tests, and rollback.

D DEVORCHESTRATE05 / Plan anatomy

What a good plan contains

PlanA.md is an engineering blueprint.

Specific enough to implement; clean enough for a developer to review. The example below is fictional.

Class- and method-level impact

ComponentActionRationale
AuthenticationServiceREUSEPreserve login flow
SecurityConfigMODIFYAdd role rules
UserControllerMODIFYGuard endpoints
PermissionEvaluatorCREATE*Only if needed
* Create only after verifying no suitable existing abstraction.

Required plan sections

Technical design: Method contracts, logic, data flow, and dependencies.
Delivery: Phases, affected files, migration steps, and rollback.
Traceability: REQ / AC mapping, test cases, and verification commands.
AdvantagesSmaller diff, reuse, lower short-term risk.
DemeritsMay retain legacy coupling or design constraints.

D DEVORCHESTRATE06 / Specialized agents

Beyond planning

Each agent has one clear responsibility.

They reuse the approved plan and share evidence—but never silently trigger the next agent.

⌘

Developer

Implements approved phases. Reuses existing code. Runs build checks. Reports actual changes.

development-report.md
◎

Code Reviewer

Checks spec, architecture, security, regressions, and maintainability with specific findings.

comments.md
✓

Unit Tester

Creates meaningful tests, executes them, and records passing, failing, or blocked results.

unit-test-report.md
⇆

Integration Tester

Validates system boundaries with real API, UI, database, or E2E evidence where applicable.

integration-test-report.md
PR Agent: Checks readiness and prepares PR details. Creating the PR requires explicit human approval.

Example: OpenCode workspace

Start with spec.md. Stay in control.

1

Set up once

Open project in Build mode. Run the master setup prompt; verify the agent files exist.

2

Write requirements

Save spec.md at the workspace root with requirements and acceptance criteria.

3

Launch Planner

Review PlanA.md / PlanB.md and comparison.md. Select or revise a plan.

4

Launch Developer

Implement the approved plan, phase by phase, with implementation reports.

5

Review and test

Invoke reviewer and testers; approve only the fixes you want.

6

Authorize PR

Review evidence, select branches, and explicitly approve PR creation.

D DEVORCHESTRATE08 / Guardrails

Built for trust

Agents can act. Humans authorize.

Agents may...

✓Inspect relevant workspace code and existing patterns.
✓Propose alternative designs with evidence and trade-offs.
✓Implement only the human-approved scope and phases.
✓Run permitted verification and document actual results.

Agents must not...

×Auto-chain through the development lifecycle.
×Silently change requirements or materially redesign plans.
×Claim successful tests without executing them.
×Commit, push, create PRs, merge, or deploy without authorization.
◆
When a plan no longer fits, stop and explain the deviation.
The human chooses whether to revise the plan, accept the trade-off, or cancel.
