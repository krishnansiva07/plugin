Execution model
04 / 05

Six agents. Six clear responsibilities.

Each agent receives an explicit task, does its scoped job, verifies what it can, writes an outcome, and stops. The developer initiates the next action.

01 · Planner

Analyses actual code, compares reusable approaches, and proposes detailed plans.

Produces plans/PlanA.md, comparison.md

02 · Developer

Implements only the approved plan phase; records changes, checks and deviations.

Produces scoped code + development-report.md

03 · Code Reviewer

Reviews the real diff, cites evidence and tracks stable findings such as CR-001.

Produces comments.md · never edits code

04 · Unit Tester

Adds or runs focused tests for functions, classes, edge cases and failures.

Produces tests + unit-test-report.md

05 · Integration Tester

Tests relevant real service, UI, API or data boundaries with safe environments.

Produces integration-test-report.md

06 · PR Agent

Checks PR readiness. Creates a PR only when separately authorised and supported.

Produces pr-summary.md · no auto-merge
Human gate → invoke one agent → review evidence → human chooses what comes next

Verified outcomes

Not just “Task completed.”

Each agent reports the actual files changed, commands and exit codes, requirement coverage, evidence, failures, blockers, and decisions still needed.

PASSFAILBLOCKEDNOT RUN

Tests are never called successful unless they actually ran and passed. An unavailable environment is BLOCKED, not PASS.

The developer remains in charge.

No hidden transitions, no autonomous fix loops, no unapproved pushes, no silently changed architecture.
